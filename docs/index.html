01 — 功能

为高频复制粘贴而设计

把系统剪贴板升级为可检索、可收藏、可回溯的历史面板，减少重复操作与信息丢失。

多类型历史记录

自动记录文本、图片和文件路径，以横向卡片列表按时间呈现，双击卡片即可复制回剪贴板。

类型化卡片样式

每条记录渲染为卡片：头部按类型着色并显示时间，正文按类型呈现文本/图片/文件/颜色等预览。

底部全宽面板

全局热键从桌面底部呼出铺满屏幕宽度的固定面板（无标题栏、不可调整大小），随时调用不打断工作流。

来源应用识别

卡片右上角显示来源应用图标：Windows 与 macOS 优先支持，Linux X11 尽力识别，Wayland 场景自动降级。

搜索、收藏与保留策略

快速筛选历史内容，★ 收藏常用片段；收藏项可在保留期限清理中保留，过期记录自动清理。

本地存储与隐私

数据保存在本地 SQLite 数据库，不依赖云端同步；支持多语言界面与透明度/毛玻璃效果（取决于系统能力）。

02 — 平台与版本

Windows 原生版 + 跨平台版并行演进

项目同时提供经典 WPF 版本与基于 Avalonia 的跨平台版本，覆盖不同使用场景。

跨平台版（OpenClipboard.App）

  • .NET 10 + Avalonia，面向 Windows / macOS / Linux（x64 / ARM64）
  • 文本 / 图片 / 文件历史，横向卡片列表与类型化卡片样式
  • 来源应用名称与图标（按平台能力支持）
  • 可配置热键、历史保留期限、透明度与界面语言
  • 支持从旧版 Windows 数据库导入历史

数据目录：各平台应用数据目录下 OpenClipboard/cross-platform.db

Windows 经典版（WPF）

  • WPF / .NET Framework 4.7.2，面向 Windows 10/11
  • 成熟的托盘体验、热键呼出与 Acrylic/Frosted 效果
  • 支持 x86 / x64 构建与安装包发布
  • 数据本地存储：%APPDATA%\OpenClipboard\database.db

适合希望在 Windows 上获得原生 WPF 体验的用户。

下载与发布

前往 GitHub Releases 获取对应平台的预编译包与安装程序。推送版本标签时将由 CI 自动构建发布产物。

03 — 快速开始

下载即用，或从源码构建

运行跨平台版（开发/源码）

需要 .NET SDK 10.0+

dotnet test src/OpenClipboard.CrossPlatform.slnx -c Release
dotnet build src/OpenClipboard.CrossPlatform.slnx -c Release
dotnet run --project src/OpenClipboard.App/OpenClipboard.App.csproj

构建 Windows 经典版

需要 .NET SDK 8.0+（目标 net472）

# 构建并打包（x86/x64）
.\build.ps1

# 生成安装包
.\build-installer.ps1
热键提示：跨平台版全局热键受系统权限与桌面环境限制；macOS 需辅助功能权限，Linux Wayland 可能受限，热键不可用时可通过托盘打开。
数据位置：WPF 版位于 %APPDATA%\OpenClipboard\database.db；跨平台版位于各平台应用数据目录下 OpenClipboard/cross-platform.db。

04 — FAQ

常见问题

OpenClipboard 会上传我的剪贴板数据吗？

不会。剪贴板历史默认保存在本地 SQLite 数据库中，不依赖云端服务。请在共享设备或敏感环境中结合自身需求使用清理与保留策略。

为什么看不到来源应用图标？

来源识别与图标提取依赖平台能力。Windows 与 macOS 优先支持；Linux 在 X11 环境下尽力匹配应用与图标，在通用 Wayland 场景会按安全模型限制自动降级（不显示来源信息），但不影响剪贴板记录功能。

全局热键按了没反应怎么办？

请检查是否与其他软件冲突，并确认系统权限（如 macOS 辅助功能权限）。在 Linux Wayland 等受限环境下，可通过托盘图标唤起窗口。

如何从旧版 Windows 数据迁移？

跨平台版本提供“Import old database...”导入能力，可将旧版 WPF 的 SQLite 历史数据导入到跨平台版数据库中（两者默认分开存储）。
